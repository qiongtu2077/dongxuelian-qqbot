# MCP 计划

## 目标

把 MCP 做成莲莲 Bot 的本地 Agent 工作台和外部工具生态层，而不是替代现有聊天 Agent 主链路。第一阶段先提供旁路 MCP Server，让 Codex、Claude、Cursor 等本地客户端可以直接查看、修改、测试和诊断本仓库；线上 QQ 聊天行为不因 MCP 开关改变。

## 总体架构

```text
莲莲 Agent Kernel
  - 群聊上下文窗口
  - 工具路由
  - 回复生成
  - 取消与过期

Tool Broker
  - 本地 JS 工具
  - 外部 MCP 工具
  - 权限分级
  - 超时与审计

Local MCP Server
  - 暴露本地诊断、读写、测试、replay 工具给 Codex/Claude
  - 默认只绑定 stdio，本地客户端显式启动

Dashboard Agent 窗口
  - 显示 MCP 启用状态
  - 启用/关闭本地 MCP 工作台
  - 配置是否允许写入、是否允许本地命令
```

## 权限分级

- `read`：读工作区文件、列目录、搜索、查 Agent 配置、查工具统计、查会话摘要。
- `write_workspace`：写入或编辑允许根目录内的本地文件，复用现有 path guard。
- `run_local`：运行本地检查命令，例如 `npm run check`、`npm run test:quick`、`npm run test:scenario`、`node -c <file>`。
- `dangerous`：部署、重启、git push、写生产 DATA_DIR、改服务器文件。默认不暴露给 MCP，仍必须用户明确确认。

## 第一阶段

第一阶段做“旁路可用”的本地 MCP Server：

- 新增 stdio MCP Server 脚本。
- 复用现有 `agent/config.js` 保存 MCP 开关。
- Dashboard 的 Agent 窗口显示 MCP 按钮，可决定启用和关闭。
- 暴露第一批工具：
  - `get_bot_health`
  - `get_agent_config`
  - `get_agent_stats`
  - `list_agent_sessions`
  - `get_agent_session`
  - `query_logs`
  - `list_files`
  - `find_files`
  - `grep_search`
  - `read_file`
  - `write_file`
  - `edit_file`
  - `run_local_check`
- 所有文件操作复用现有允许根目录和阻断规则。
- 日志和命令输出走脱敏。
- MCP 不自动接入 QQ 群聊工具列表，不改变线上回复链路。

## 第二阶段

补完整诊断黑匣子：

- 给每次聊天、随机回复、Agent 自动路由生成 `traceId`。
- 记录 active scene 摘要、引用链、媒体/文件锚点、工具决策、模型响应类型、发送结果。
- 新增 `inspect_interaction(traceId/messageId)`。
- 新增 `search_interactions`。
- 只保存安全索引和摘要，不保存真实本地路径、token、cookie、真实 URL、文件正文。

## 第三阶段

做离线 replay：

- `run_offline_replay` 默认使用临时 `DONGXUELIAN_AI_DATA_DIR`。
- 可复现用户输入、active scene、工具选择和发送层前的最终回复。
- replay 不写生产 data，不触发真实 QQ 发送。

## 第四阶段

让 bot 作为 MCP client 接入外部工具：

- 新增 Tool Broker，统一本地工具与 MCP 工具。
- 外部 MCP server 必须白名单配置。
- 群聊调用外部 MCP 工具必须经过权限、超时、脱敏和工具结果清洗。
- 先支持只读知识库、文档检索、GitHub issue 查询，再考虑可写工具。

## 验收标准

- Dashboard Agent 窗口能看到 MCP 开关，并能保存启用/关闭状态。
- 本地 MCP Server 在关闭时拒绝工具调用。
- 开启后本地客户端能列出工具并调用只读诊断工具。
- 写文件和编辑文件只能发生在允许根目录内。
- 本地命令只允许固定检查命令，不允许部署、重启、push。
- `npm run check` 或至少新增模块 `node -c` 通过。
