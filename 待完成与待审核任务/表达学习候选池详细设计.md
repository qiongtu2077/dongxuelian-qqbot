# 表达学习候选池详细设计

## 状态

暂缓实现。先完成 `persona.schema.v1`、`PersonaRuntimePlan`、`chat-prompt-builder`、`persona-lore-router`、`reply-timing` 和 `persona-profile` 的前置链路，再进入本设计。

## 核心目标

表达学习不是让 Bot 立刻学会群聊里的所有词，而是把“可能值得学的表达”从聊天流里捞出来，经过风险规则、人格兼容性和人工审核后，少量、克制地作为风格候选使用。

## 最大风险：OOC

群聊高频表达不一定适合所有人格。一个词对东雪莲可能自然，对长离、特蕾西娅、爱弥斯可能直接串味。

因此候选表达不能是全局词库，必须带：

- 适用人格
- 禁用人格
- 适用群
- 适用场景
- 情绪标签
- 风格强度
- 风险标签
- 过期时间
- 审核状态

## 候选数据结构

```js
{
  id,
  text,
  meaning,
  examples: [
    { channelKey, messageId, shortQuote, ts }
  ],
  scope: 'channel' | 'persona' | 'global',
  channelKey,
  allowedPersonas: [],
  blockedPersonas: [],
  moodTags: ['tease', 'surprised'],
  riskTags: [],
  styleStrength: 0.2,
  status: 'candidate' | 'reviewed' | 'blocked' | 'expired',
  useCount: 0,
  positiveFeedback: 0,
  negativeFeedback: 0,
  createdAt,
  expiresAt
}
```

## 人格表达策略

每个人格需要在 plan 里声明表达学习策略：

```js
{
  expressionPolicy: {
    allowLearnedExpressions: true,
    maxStyleStrength: 0.2,
    allowedMoodTags: ['calm', 'brief_tease'],
    blockedMoodTags: ['cute', 'meme_spam', 'aggressive'],
    bannedExpressionIds: [],
    injectionMode: 'abstract' // concrete | abstract | disabled
  }
}
```

强人格默认更保守：

- 长离：优先 `abstract`，低强度，禁网络热词。
- 特蕾西娅：默认 `disabled` 或极低强度。
- 爱弥斯：允许理性、克制、轻微调侃，禁卖萌。
- 东雪莲：可以更高强度，但仍要禁越狱、隐私和恶意攻击。

## 注入规则

候选进入 prompt 前必须同时满足：

- `status === 'reviewed'`
- 当前人格允许表达学习
- `allowedPersonas` 为空时不能给强人格默认使用
- 当前人格不在 `blockedPersonas`
- `styleStrength <= persona.expressionPolicy.maxStyleStrength`
- `moodTags` 与当前场景匹配
- 当前群/私聊 scope 匹配
- 本轮没有严肃、敏感、拒绝、低落安慰等禁用场景

注入方式分两类：

- `concrete`：可以给出具体短语，但每轮最多一个。
- `abstract`：只给抽象风格提示，不给原词，适合强人格。

## 明确不做

- 不自动修改人格文件。
- 不把用户个人口癖默认变成 Bot 口癖。
- 不把群 A 的黑话默认带到群 B。
- 不学习私密命令、token、日志、工具输出。
- 不学习越狱模板、攻击性表达、隐私信息、真实身份猜测。
- 不让未审核 candidate 进入线上 prompt。

## 测试故事

- 高频脏话进入 blocked，不进入 prompt。
- “猫娘”类表达对东雪莲、长离、爱弥斯 blocked。
- 群 A reviewed 表达不进入群 B。
- 长离只收到 abstract 风格，不收到具体热词。
- 用户说“别学我说话”后，相关候选降权或 archived。
- 每轮最多注入一个 reviewed 表达。
- 严肃/敏感/安慰场景不注入玩梗表达。
