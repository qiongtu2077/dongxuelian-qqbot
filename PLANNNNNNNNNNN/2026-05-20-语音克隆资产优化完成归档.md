## 关键实现记录

### 元数据与兼容

- 新增 `DATA_DIR/ai-voice-assets.json` 保存资产元数据，不把显示名写进物理文件名。
- 旧模型中 `voice_id: __cloned__` 仍然可用。
- 新模型中人格可带 `voice_asset_id`，运行时优先按资产 ID 找样本；缺失时回退旧的人格名样本。

### Dashboard 管理能力

- 上传克隆音频时可设置显示名、备注、试听文本。
- 已克隆音色列表展示绑定人格、更新时间、大小和当前启用状态。
- 试听走既有 `/dashboard/api/agent/tts/preview`。
- 保存只更新元数据，不重命名样本文件，避免破坏运行时查找。
- 删除前检查引用者；有引用时返回引用人格，需强制确认才删除。

### TTS 模型约束

- 语音克隆仍使用 `mimo-v2.5-tts-voiceclone`。
- 普通 TTS 仍使用 `mimo-v2.5-tts`。
- 本次没有改变第三方模型的输入协议和外部扣费链路。

## 测试四问

1. 复现了用户哪条真实失败输入？

   语音优化不是单条聊天输入事故，而是 Dashboard 管理能力缺口。覆盖的真实操作路径包括：
   - 选择人格后上传克隆音频。
   - 为克隆音色填写显示名、备注、试听文本。
   - 从已克隆列表试听、启用、保存、删除。
   - 多个克隆版本绑定到同一人格或被多个人格复用。

2. 断言了哪个失败现象不会再出现？

   - 上传后的克隆音色不再只能显示为笼统的“克隆音色”。
   - 同一人格重复上传不再覆盖旧样本。
   - 删除仍被人格引用的音色前不会静默破坏绑定。
   - `voice_asset_id` 缺失或旧数据仍能回退到原有 `__cloned__` 样本查找。

3. 哪些依赖被 mock 了？

   - 语音场景测试使用临时 `DONGXUELIAN_AI_DATA_DIR`。
   - Dashboard 点击 smoke 使用本地模拟页面/接口环境，不调用生产 Dashboard。
   - 外部 MiMo TTS/voiceclone API 没有在测试中真实扣费调用。
   - QQ/NapCat/Koishi 生产传输链路未参与本地验证。

4. 因为 mock，哪些真实链路仍未覆盖？

   - 未覆盖真实服务器 Dashboard 上的上传、试听、删除操作。
   - 未覆盖真实 MiMo 语音克隆和 TTS 扣费链路。
   - 未覆盖真实 QQ 语音消息发送链路。
   - 未执行服务器部署或重启；部署/重启仍需用户明确确认。
